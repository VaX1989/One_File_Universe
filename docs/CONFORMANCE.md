# Conformance Model

Conformance exists to make OFU claims falsifiable. Passing on one developer machine is not portability.

## Layers

Artifact conformance checks the one-file release and declared embedded payloads. Bootstrap conformance checks direct-open, offline behavior and controlled capability degradation. Canonical-kernel conformance checks deterministic addressing, derivation, numeric primitives, canonical serialization, hashing and bounded decode/encode behavior. Generator conformance uses golden vectors and invariants. Temporal conformance covers event ordering, replay, checkpoints and portable state. Runtime independence requires Golden Universe Corpus equality across the declared executed matrix. Performance budgets remain observational and cannot silently change canonical semantics.

P2's normative byte contract is `docs/P2_PROTOCOL.md`; its evidence contract is `docs/P2_SECURITY_CONFORMANCE.md`.

## Runtime profiles

Strict Direct-Open requires local single-file launch, no required network, no secure-context-only dependency, no SharedArrayBuffer dependency, portable authoritative save/export and capability-aware rendering fallback. Enhanced capabilities may include WebGPU, origin-bound storage and SharedArrayBuffer where available. Enhanced and Strict must produce the same canonical corpus for the same Universe Identity/protocol.

## P2 executed-target contract

The automated matrix is Linux x64 Chromium/Firefox/WebKit, Windows x64 Chromium and macOS ARM64 WebKit. Each report records runtime versions, platform/architecture, direct-open protocol and canonical digests. The aggregate gate requires every target exactly once and requires direct/Worker-1/reordered Worker-2/Worker-4 agreement.

Playwright WebKit MUST NOT be labeled Safari verification. Real Safari/iOS is `NOT_VERIFIED` unless executed directly.

## Golden Corpus and properties

The Golden Universe Corpus is a normative versioned artifact generated by the Python oracle and checked by JavaScript. It covers primitive and integer boundaries, Unicode normalization/rejection, canonical maps, all address segment types and address boundaries, malformed byte/address rejection, identities, derivation, numeric rules, resource boundaries and a reproducible generated corpus. Unknown oracle kinds fail closed.

P2 tests `encode(decode(encode(v))) === encode(v)`, canonical-byte re-encoding, rejection of alternate aliases, map permutation invariance, NFC/NFD normalization, normalized-key collision rejection, identity/domain separation, global traversal/byte budgets, worker/order independence and deterministic pinned-seed mutation fuzzing.

## Save conformance

Portable save testing covers export/import round trip, integrity failure, version/manifest mismatch and bounded input. Export and import enforce the same final portable-save size domain; the implementation must not successfully export a save that it rejects solely because of that final size bound.

## Evidence and gates

Use the project evidence taxonomy precisely; do not collapse `PARTIAL`, `ENVIRONMENT_LIMITED` or `NOT_VERIFIED` into `PASS`. P2 evidence is typed by declared kind and pinned to one exact source commit. Filename matching is not evidence typing.

P1 remains a required regression gate for P2. P2 closes only after the exact candidate SHA passes Foundation Integrity, P1 Conformance and P2 Conformance; review findings are adjudicated; reproducible-build/security/performance evidence exists; the PR is merged without bypassing red checks; and the exact merged `main` passes post-merge verification. P3 is blocked until those conditions are met.
