# Governance Maturity and Bus Factor

OFU distinguishes architecture prepared for scale from a community that has actually achieved scale.

The current machine-readable stage is `BOOTSTRAP` in `config/governance/community-resilience.json`. This is intentional and accurate: the repository currently has scalable ownership/risk/integration structures, but bootstrap ownership still depends on the founder.

Maturity advances through `EMERGING_COMMUNITY`, `DISTRIBUTED_MAINTAINERSHIP` and `COMMUNITY_RESILIENT` only when the documented evidence exists. The targets include multiple maintainers in every critical area, several qualified integration maintainers able to rotate the one-active integration lease, private security reporting, reviewed contributor-rights infrastructure, organization teams and eventually a tested succession path.

Contributor count alone is not resilience. A repository with 1,000 casual contributors and one person able to merge/release remains a bus-factor-one project.

The resilience ledger is governance evidence, not a ranking of people. It should be updated from verifiable maintainer/team state and must never be advanced merely to improve project optics.
